# Push it

Commit the current changes, integrate the latest upstream work, and push the resulting HEAD to `origin/main`. Invoking this skill authorizes the commits, merges, conflict resolution, verification, and push needed to finish. Continue autonomously without asking for confirmation merely because main has advanced, histories have diverged, or conflicts need resolving.

1. Read repository instructions. Inspect Git status, staged and unstaged diffs, and untracked files. Include all current changes unless the user narrows the scope; exclude credentials and files prohibited by repository instructions, and report any exclusions. Inspect any unfinished merge or rebase: continue it when it belongs to this task; preserve unrelated in-progress work rather than aborting or overwriting it.
2. Verify the existing `origin` remote and fetch its `main`. Review local and upstream commits. Complete the required verification for local changes, reusing relevant results when the files have not changed, then stage the included changes and commit with a concise message describing the diff. Skip this commit if there are no changes. Preserve excluded or unrelated work before integrating upstream; do not discard it.
3. If `origin/main` is not an ancestor of HEAD, merge it into the current checkout with `git merge --no-edit origin/main`. Prefer a merge to rewriting existing commits; allow a fast-forward when possible. Resolve conflicts autonomously by inspecting both sides, their intent, surrounding code, and relevant tests. Preserve the intended behavior of both changes rather than choosing ours or theirs wholesale. Check for semantic conflicts even in automatically merged files. Run verification appropriate to the combined changes, fix regressions, stage the resolutions, and complete the merge commit.
4. Run `git push origin HEAD:refs/heads/main`. This works from another branch or detached HEAD without switching branches. Treat a successful push response as completion; do not perform a follow-up fetch or remote-SHA comparison. If rejected because main advanced again, fetch, inspect, merge, resolve conflicts, verify affected behavior, and retry autonomously. Allow up to three such recovery attempts per invocation; report continued upstream churn rather than looping indefinitely. Report the pushed commit SHA briefly, or say that `origin/main` was already up to date. Never claim success after a failed push.

Do not force-push, reset away work, change remotes, or bypass hooks, branch protection, or approval controls. Ordinary divergence and resolvable conflicts are work to complete, not reasons to stop. Pause only for a concrete blocker that requires user input or access, such as a missing remote/main, unrelated in-progress Git work whose intended outcome is unknown, an unresolved product decision after inspecting the available evidence, or a failed permission/protection gate. State the precise blocker and preserve completed work.
